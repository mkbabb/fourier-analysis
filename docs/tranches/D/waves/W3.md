## §4 — The typed `ImageAsset` Pydantic model (the C9/C10 root-fix transposition)

The transposition: lift the asset to a `pydantic.BaseModel` whose load-bearing fields are declared + typed.

### Step T1 — declare `ImageAsset` in `api/models/assets.py`

The model carries every field the asset code reads, with **the post-C.W5 cutover shape** (no `blob`, no inline `thumbnail`):

```python
# api/models/assets.py — add to the existing module
class ImageAsset(BaseModel):
    """The image-asset document shape (the C.W5 post-cutover form).

    Every field a live consumer reads is declared + typed here. The class
    of bug C9 (existing["blob"] KeyError on a migrated doc, swallowed by a
    broad except) and C10 (the {"blob": 1} inclusion-mode projection
    starving the shim) is structurally foreclosed by the typed contract:
    a projection that omits a required field becomes a Pydantic validation
    error at construction time, not a KeyError swallowed deeper in the call
    chain.
    """
    image_slug: str
    sha256: str
    original_name: str
    content_type: str
    bytes: int
    storage_uri: str                              # the C.W5 deletion-proof field
    thumbnail_uri: str | None = None              # may be absent (the no-thumbnail case)
    thumbnail_content_type: str | None = None
    created_at: datetime
    last_accessed_at: datetime
    pinned: bool = False                          # janitor recency-prune flag
```

`model_config = {"extra": "ignore"}` — Mongo `_id` and other surplus fields pass through harmlessly; the validator binds only the fields the asset code reads, not the document's full shape.
