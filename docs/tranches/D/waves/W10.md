### §2.2 — The `certbot --expand` script (tracked, new) — the LE expand mechanics

W10 authors `scripts/certbot-expand-api.sh` (tracked). It carries the binding invocation but **runs only on the host** (the certbot binary, the CF DNS-01 plugin, the credentials file all live at host paths). The script body:

```bash
#!/usr/bin/env bash
# D.W10 — extend the live LE cert (sudoku.babb.dev) with api.<app>.babb.dev SANs.
# READS: /etc/letsencrypt/cloudflare.ini (root:root 0600 — token from gitignored .env).
# RUN ON THE HOST as root (sudo).
set -euo pipefail

CERT_NAME="sudoku.babb.dev"     # the existing LE cert name (already on prod)
CREDS="/etc/letsencrypt/cloudflare.ini"

# Existing SANs (NA5 §1.4): fourier/sudoku/words.babb.dev
# Adding: api.fourier.babb.dev, api.color.babb.dev, api.sudoku.babb.dev
certbot certonly \
    --expand \
    --cert-name "$CERT_NAME" \
    --dns-cloudflare \
    --dns-cloudflare-credentials "$CREDS" \
    --dns-cloudflare-propagation-seconds 30 \
    -d sudoku.babb.dev \
    -d fourier.babb.dev \
    -d words.babb.dev \
    -d api.fourier.babb.dev \
    -d api.color.babb.dev \
    -d api.sudoku.babb.dev \
    --non-interactive --agree-tos --email mike@babb.dev

# Verify the SANs
openssl x509 -in "/etc/letsencrypt/live/${CERT_NAME}/fullchain.pem" -noout -text \
    | grep -A1 "Subject Alternative Name"

# Dry-run the renewal — proves the new SANs renew via DNS-01 cleanly
certbot renew --dry-run --cert-name "$CERT_NAME"
```

The credentials file `/etc/letsencrypt/cloudflare.ini` is host-managed (`root:root 0600`); its content is one line `dns_cloudflare_api_token = <the-token-value>`. **The script does NOT write the credentials file** — that is an operator pre-condition. The script reads the file via the certbot plugin (no plaintext exposure beyond `0600` `root:root`).

**No `pip install certbot-dns-cloudflare`** new step — the plugin should already be present on the host (`apt install python3-certbot-dns-cloudflare` is the Ubuntu package); the script's pre-flight: `certbot plugins | grep -q dns-cloudflare` else exit non-zero with a clear install instruction.

## §7 — Failure-mode contract

| Mode | Required behaviour |
|---|---|
| `certbot --expand` fails on DNS-01 challenge | Likely cause: the api A record hasn't propagated (W8 G7 not yet green). Re-verify `dig +short api.fourier.babb.dev` returns `34.197.214.67` first; re-run the expand with `--dns-cloudflare-propagation-seconds 60`. **Do not** silently fall through to webroot challenge (would 404 — the api endpoint serves nothing pre-vhost). |
| LE rate-limit hit (5 duplicates per week, 50 certs per registered domain per week) | Recoverable: the expand is one operation across six names — well under the per-domain limit. If hit anyway, wait the documented window; do NOT migrate to a different CA without explicit authorization. |
| Apache `configtest` fails on the new vhost | Most common cause: a missing module (`proxy_http`, `headers`) or a typo in `localhost:<gateway-port>`. Apache modules already enabled (NA5 §1.3 evidence: `proxy.load`, `proxy_http.load`, `headers.load`, `ssl.load`, `rewrite.load` all enabled). Fix the typo + re-test before reload. |
| `systemctl reload apache2` fails or partially fails | The vhosts are not yet active; the prior config still serves. **Do not declare W10 green**. Diagnose, fix the configtest, reload. |
| The api endpoint behind the vhost returns 502 / 503 | Likely cause: the per-app nginx gateway is not running (`docker ps` shows no `*-nginx-1` for the app), or the backend container is not running. Verify the docker stack; restart per-app compose if needed. |
| CORS preflight returns 200 but no `Access-Control-Allow-Origin` header | The CORS middleware is bypassed (e.g. the `OPTIONS` request didn't hit the FastAPI app — host Apache or per-app nginx is short-circuiting). Verify `nginx/<app>.conf` does not have a hand-written OPTIONS handler that returns 200 without the headers. |
| CORS preflight returns 200 but `Access-Control-Allow-Origin: *` (instead of echoing the exact origin) | Wrong middleware mode — `allow_credentials=True` requires echoing the exact origin, not `*` (NA5 §2.1 + `api/main.py:55-62`). The fourier impl is correct; this would be a regression. **Reject the preflight as a fail**; never accept `*` with credentials. |
| W1's Mongo bind regressed (a `0.0.0.0:27017` listener appears) | W10 G13 fails. Halt W10 close; re-run W1's Mongo-bind step (the compose `ports:` edit) before any browser hits `api.<app>.babb.dev` for a backend that talks to that Mongo. |
| The palette-api CORS edit's container restart fails | The standalone palette-api repo's `compose.yaml` is the source; a failed restart leaves the prior empty `ALLOWED_ORIGINS` in place — the CF Pages frontend's preflight fails. Roll forward (fix the compose), not back (the empty value is itself the bug). |
