## Goal criterion

W4 succeeds when the repo's scaling, KISS, and correctness surfaces are sound: the janitor no longer builds an unbounded pinned-id set; the rate-limiter's process-local state is documented honestly rather than hidden behind a silent-fail-under-replication contrivance; the contour-hash collision that mis-serves saved contours is fixed and pinned by a regression test; the three dead modules (`logo.ts`, `math-worker.ts`, `compute.py`) retire; the Mongo password leaves source. The aim is invariant 12 (scale without contrivance) and invariant 8 (numerical correctness precedes UI polish) bound to a clean substrate for tranche B (the *CRUD / identity convergence* tranche) — B inherits `image_storage.py` with the hash bug behind a passing test and `gallery.py` with one paginated list path.

## Scope

Audit `e-crud-slug-valuejs.md` and `f-design-math-functionality.md` named the live risks; W4 applies the *smallest* honest fix to each.

1. **Janitor pinned-set inversion.**
   - *Goal*: the janitor's query no longer scales with the pinned-id cardinality; it scales with the unpinned set.
   - *What*: `api/services/janitor.py` currently builds an unbounded pinned-id set and passes it as `{"$nin": [...]}` — the list grows past the 16 MB BSON limit and defeats indexes. Invert to a per-document `pinned` boolean flag; the janitor queries `{pinned: false, ...}`.
   - *Why*: invariant 12 (scale without contrivance) — the unbounded `$nin` is a contrivance dressed as policy; a boolean flag is the smallest honest mechanism.
   - *Completion*: a janitor test asserts no unbounded `$nin` construction; the query under the new flag runs against an indexed predicate.

2. **Process-local state — honest, not hidden (rate-limiter).**
   - *Goal*: the rate-limiter's process-local state is either documented honestly under a single-replica constraint, or moved to a Mongo TTL collection if single-replica is not viable.
   - *What*: the `rate_limiter` buckets and the `_suspended_cache` are process-local; they fail silently under more than one replica. W4 does *not* add Redis (no superfluous cloud — invariant 12). It either (a) documents a single-replica constraint explicitly in `docker-compose.prod.yml` and a deploy note, or (b) moves the bucket to a Mongo TTL collection if the W0 challenge step shows single-replica is not viable. The decision is taken at W0 (the *Open, challenge, hygiene, numerical-test repair* wave); W4 executes it.
   - *Why*: invariant 12 again — "scales silently to zero correctness under replication" is the contrivance; pinning `replicas: 1` in the deploy surface is the honest mechanism.
   - *Completion*: the W0-challenge decision lands in source; the deploy-surface constraint is documented at `audit/W4-deploy-note.md`.

3. **Contour-hash correctness bug.**
   - *Goal*: distinct contour curves never collide on the storage hash; a regression test fails on the old hash and passes on the new.
   - *What*: `store_contour_asset` hashes `sorted(xs)` and `sorted(ys)` independently (at `api/services/image_storage.py:180`, per H3 hardening — audit E cited `:165`, which was off by 15 lines); distinct curves sharing coordinate multisets collide, and a collision serves the wrong contour. Rehash on the *ordered coordinate pairs*. Ship a regression test with the H3-specified pair — `xs=[0,1], ys=[0,1]` (positive diagonal) vs `xs=[0,1], ys=[1,0]` (negative diagonal), identical sorted axes but distinct ordered pairs — plus a secondary 3-point triangle pair for robustness. This is the only correctness fix in W4; the structural restructure of `image_storage.py` belongs to tranche B.
   - *Why*: invariant 8 (numerical correctness precedes UI polish) — a collision that mis-serves contours is a correctness defect, not a polish concern; A keeps it because correctness does not wait for a research tranche.
   - *Completion*: `test_contour_hash.py` exists, fails on the pre-W4 hash, passes after; the test output is captured in `PROGRESS.md`.

4. **Dead-code deletion.**
   - *Goal*: the three unconsumed modules retire under a deletion proof.
   - *What*: delete `web/src/lib/logo.ts` (100 LOC, zero consumers — `generateEpicycleLogoPath` and kin), `web/src/lib/math-worker.ts` (55 LOC, never instantiated, carrying the placeholder `y[i] = t` non-math), and `api/routers/compute.py` (a tombstone). Deletion proof: `git grep` shows no import.
   - *Why*: invariant 5 (no overfitting) — a public surface with no consumer is dead weight.
   - *Completion*: the three files do not exist; `git grep` finds no import of any of them.

5. **Gallery endpoint consolidation.**
   - *Goal*: one paginated gallery list path remains, with no `count_documents` on the hot path; admin callers migrate to that path before the duplicate drops.
   - *What*: `count_documents` (O(n)) runs on every gallery list including the cursor endpoint, and the offset and cursor gallery endpoints duplicate each other. Keep the cursor endpoint, drop the offset duplicate, drop the per-list `count_documents` — cursor pagination needs no total. **H3 hardening flagged a caller migration**: `web/src/stores/gallery.ts:32 fetchPage()` still drives admin actions (`setTier`, `deleteEntry` at `:137,149,189,207`) via the offset endpoint. W4.b migrates those callers to the cursor path *before* dropping `GET /api/gallery`, or the consolidation regresses admin. Tranche B later restructures gallery into the `visualization` entity; W4 only removes the O(n) hot-path drag — it does not redesign.
   - *Why*: invariant 1 (KISS / DRY) — two paginated paths over the same collection is one too many; invariant 12 forbids the silent O(n) on every list.
   - *Completion*: the gallery has one paginated list endpoint; no `count_documents` on the hot path; admin callers exercise the cursor path before the offset endpoint drops.

6. **Secrets out of source.**
   - *Goal*: no literal Mongo password sits in tracked source.
   - *What*: the hard-coded MongoDB password lives at **3 sites** (per H3 hardening — audit E reported 2 by missing the healthcheck): `docker-compose.yml:14`, `docker-compose.prod.yml:8`, and the prod healthcheck `mongosh -p` at `docker-compose.prod.yml:47`. All three move to an env reference; `.env.example` documents the variable.
   - *Why*: a literal credential in a tracked compose file is a leak surface; the smallest honest fix is an env reference.
   - *Completion*: `git grep` for the password string returns nothing; `.env.example` documents the new variable.

7. **Rate-limiter decision (per W0 challenge).**
   - *Goal*: the rate-limiter's replica-safety question gets a recorded decision that survives the close ceremony.
   - *What*: H3 recommends **Option A — single-replica documented honestly**, pinning `docker-compose.prod.yml` to `deploy.replicas: 1` plus a deploy note at `docs/tranches/A/audit/W4-deploy-note.md`. Prod is already single-replica; invariant 12 is satisfied by documenting the constraint, not by adding Redis. Option B (Mongo TTL bucket) is the future move and is named as fourier tranche C debt; Option C (delete + nginx edge limit) requires an nginx change and is not free.
   - *Why*: invariant 7 (no silent deferral) — the W0-challenge decision needs a destination in source; invariant 12 makes Option A the smallest honest mechanism.
   - *Completion*: `docker-compose.prod.yml` carries `deploy.replicas: 1`; `audit/W4-deploy-note.md` records the constraint and names the Option B → tranche C destination for the future move.
