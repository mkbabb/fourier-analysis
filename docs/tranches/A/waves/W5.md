   - *Goal*: the admin moderation surface stops dropping to native browser primitives and renders the glass-ui idiom across destructive dialogs, selection controls, pagination, and rows.
   - *What*: replace native `confirm()` destructive dialogs with the glass-ui `Dialog`; native `<select>` with the glass-ui `Select`; the hand-rolled `Prev / Next` pagination with the glass-ui pagination component; bare `border bg-card/50` rows with the shared `cartoon-card` / glass-ui surfaces.    - *Why*: invariant 10 (token-first, component-over-CSS-class) and invariant 9 (surface-appropriate evidence) — the admin surface is visibly the lowest-fidelity in the app; the same primitive vocabulary the consumer view uses must reach it.
   - *Completion*: `git grep` for native `confirm()` or `<select>` in the admin tree returns zero; the a11y check passes; every icon-only control has an accessible name.

2. **Audit-log viewer.**
   - *Goal*: the live `/api/admin/audit` endpoint renders in the UI as a tab the moderator can open, with the existing `AuditListResponse` shape consumed.
   - *What*: the backend is complete — `api/routers/admin.py:542` ships `/api/admin/audit`, with `AuditEntry` / `AuditListResponse` already in `web/src/lib/types.ts` — but there is no viewer component and no tab.    - *Completion*: `AdminAuditLog.vue` exists, has a tab in the admin host, and renders live entries (browser observation, screenshot saved).

3. **Batch multi-select UI + contract bug.**
   - *Goal*: the batch endpoints `admin.py:362-451` carry a multi-select UI that round-trips, riding API-client wrappers whose return types match the backend.
   - *What*: `admin.py:362-451` ships `batch_gallery` / `batch_users` endpoints with no multi-select UI. Add the selection affordance and wire it. **H3 surfaced a latent contract bug**: the API-client wrappers at `web/src/lib/api.ts:526,537` declare a `{ processed }` return shape, but the backend returns `{ ok, affected }` — W5 fixes the wrapper return types to match the backend before wiring the UI, otherwise the UI ships against a broken type contract.
   - *Why*: invariant 4 again (the batch endpoints are substrate without a consumer) and invariant 6 (gates close on evidence — a wrapper whose return type disagrees with the backend never round-trips correctly).
   - *Completion*: batch multi-select round-trips against `batch_gallery` / `batch_users` (browser observation); the wrappers' return types match the backend.

4. **Math-honesty fixes.**
   - *Goal*: the two user-visible math defects on the figure surfaces close, with the fix matching the convention in `paper/fourier_paper.tex`.
   - *What*: invariant 8 — these are visible to the user:
     - `FrequencyGraph.vue` log-scale mode applies an un-annotated `log10(amplitude+1)` against an unlabeled axis — label the axis and annotate the transform.
     - `ConvergencePlot.vue` — the original curve stops one sample short because the backend integrates with `endpoint=False`; correct the off-by-one so the plotted original curve closes. The fix matches the convention in `paper/fourier_paper.tex`.
     - Confirm no convergence or equation surface depended on the `math-worker.ts` placeholder deleted at W4 (the *Scaling, KISS and correctness pass* wave).
   - *Why*: invariant 8 (numerical correctness precedes UI polish) — an un-annotated transform and an off-by-one on a figure surface are correctness defects in the user-visible mathematics, not styling concerns.
   - *Completion*: the `FrequencyGraph` log axis is labeled and the transform annotated; the `ConvergencePlot` original curve closes; screenshots before / after captured.
