# A.W3.5 — Paper-texture + dark-mode root fix

A.W3.5.ab — the cross-repo substrate-fix discipline applied to the paper-texture
opacity disparity that surfaced after the W2.a token-de-fork pass. The fix lands
upstream in `@mkbabb/glass-ui` (the canonical home for the `--paper-clean-texture`
and `--paper-aged-texture` tokens); no fourier-side override of the texture
opacity is introduced.

## §0 — Goal criterion / completion criterion

**Goal.** Restore the canonical subtle paper-texture register the fourier paper
view depended on prior to the glass-ui v2.0.0 migration — by fixing the wrong
upstream default (`opacity='1'` baked into the SVG-noise data URI), not by
masking it with a consumer-side carry.

**Completion.** When the glass-ui `--paper-clean-texture` / `--paper-aged-texture`
URIs are restored to `opacity='0.04'` / `opacity='0.06'` (the fourier-original
values pinned at `4df1a06:web/src/style.css:53-54`), and the fourier consumer
renders the paper register subtly in both light + dark mode without any
fourier-side override of those tokens. The dark-mode "salmon/orange section
heading" artefact dissolves as a downstream consequence (it was a tone-perception
artefact of the heavy grain field multiplying against the warm dark cream
background, not an independent token-fork).

## §1 — Root cause

Two distinct claims under the directive:

### §1.a — Paper-texture (the principal fault)

`@mkbabb/glass-ui/src/styles/tokens.css:1023-1024` ships:

```css
--paper-clean-texture: url("data:…feTurbulence baseFrequency='0.65' numOctaves='4'…rect opacity='1'/>…");
--paper-aged-texture:  url("data:…feTurbulence baseFrequency='0.5'  numOctaves='5'…rect opacity='1'/>…");
```

The fourier-original (pre-W2.a token-de-fork) at `4df1a06:web/src/style.css:53-54`
shipped the same `feTurbulence` parameters but with `opacity='0.04'` (clean) and
`opacity='0.06'` (aged) — the canonical subtle register. Glass-ui's
`opacity='1'` produces an overt, grainy field that distorts every consumer of
`.paper-texture` (the App.vue shell in fourier consumes it at line 23 — the
class is defined upstream at `glass-ui/src/styles/cards.css:10-15`).

The SVG `opacity` attribute is baked at parse-time and cannot read a CSS variable
(SVG presentation attributes resolve in the SVG document context, not the host
CSS context). The only correct fix is to inline the subtle value at the URI
source — i.e. in `glass-ui/src/styles/tokens.css` directly. Consumers needing
a heavier overlay must layer a wrapping element with its own `opacity:` /
`mix-blend-mode:` atop, not override the texture itself.

### §1.b — Dark-mode tokens (the secondary claim — investigated, no root fix needed)

The directive named a "salmon/orange tint" in dark-mode section headings as a
suspected second token disparity. Investigation:

- Fourier consumes `--section-color-{0..12}` (`PaperSidebar.vue:76,98,114`,
  `MobileFloatingToc.vue:137`) and `--accent-pink` (`EditorControlsDock.vue:201`,
  `MorphShapePreview.vue:172-173`, `FourierMorphDemo.vue:41`). Fourier does NOT
  consume `--section-heading` (which the W2.a pass deleted from fourier's local
  fork).
- Glass-ui's dark-mode `.dark` block at `tokens.css:1280-1330` ships
  `--section-color-0..12` with **bit-identical** values to fourier-original
  at `4df1a06:web/src/style.css:.dark` (the brighter dark palette: rose
  `334 72% 70%`, purple `272 54% 73%`, …, periwinkle `256 60% 74%`). The
  `--accent-pink: hsl(335 55% 65%)` dark value also matches.
- The "Introduction" section heading in the captured dark-mode-before
  screenshot reads warm rose-pink — that is the canonical `--section-color-0`
  fourier-original value, not a regression.
- The "salmon/orange" perception was a symptom of the §1.a fault: the heavy
  grain field at `opacity='1'` rendered as a beige-toned multiply-blend overlay
  atop the dark cream background, distorting tone reading of the warm
  section colours. Fixing §1.a dissolves the perception artefact.

No dark-mode token edits are needed. The W2.a token-de-fork stands: glass-ui's
dark palette IS fourier's canonical dark palette.

## §2 — The architectural fix

**Option A (chosen) — restore canonical subtle opacity in glass-ui.** The two
URIs in `glass-ui/src/styles/tokens.css:1023-1024` are rewritten to
`opacity='0.04'` (clean) and `opacity='0.06'` (aged), inlined directly into the
data URIs. A comment block above the tokens documents the substrate constraint
(SVG `opacity` cannot read a CSS var, so the subtle value must be baked) and
the architectural directive (heavier-overlay consumers layer atop, not override
the texture).

**Option B (rejected) — make tunable via CSS var.** SVG presentation attributes
do not resolve CSS vars; this is structurally impossible without rewriting the
texture-application channel (e.g. a wrapper element with `opacity: var(...)`
on the host instead of on the SVG rect). The rewrite would touch every
glass-ui consumer of `.paper-texture` and is disproportionate to the fix.
Option A is the smallest correct intervention.

The unrelated `.paper-underpaint` and `.paper-grain-overlay` utilities at
`glass-ui/src/styles/paper.css` use their own baked `opacity='1'` URIs but
SCALE them down via `opacity: var(--glass-grain-opacity)` at the CSS layer
(default `0.025`). Those utilities are not broken — the opacity is applied at
the host element, not at the SVG rect — and were left untouched.

## §5 — Disposition

The texture fix is empirically discharged at glass-ui (the rebuilt
`dist/styles/tokens.css` ships the subtle URIs; the fourier consumer renders
clean in both modes after a `node_modules/.vite` reset and vite restart).

The glass-ui `npm run build` step crashed during the dts (api-extractor)
validation phase with an unrelated pre-W2.f plugin defect
(`vite-plugin-dts` referencing a missing `dist/src/components/ui/tooltip/Tooltip.vue.d.ts`).
This crash is downstream of the `closeBundle` step where the
`publishStyleAssets` plugin runs — `dist/styles/tokens.css` is regenerated
BEFORE dts fails, so the consumer-visible CSS surface ships correctly. The
dts crash is an upstream glass-ui concern outside this work's bounds; it is
not introduced by the W3.5.ab edit.

**Residual carries: none.** No fourier-side override of `--paper-clean-texture`
or `--paper-aged-texture` exists in `web/src/style.css` — the file is
unchanged. The W2.a token-de-fork posture is preserved; the W3.5.ab fix
flows from upstream.

The carry is recorded as `DISCHARGED at glass-ui <hash>` in
`coordination/CONSTELLATION.md` as a new Emitted row (the paper-texture
opacity carry is a distinct surface from the prior font-asset URL hygiene
carry, so it is filed as a new row rather than folded into the existing
font-asset entry).
