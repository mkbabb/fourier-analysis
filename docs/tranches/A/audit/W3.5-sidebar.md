# W3.5.c — PaperSidebar glass-ui leverage

**Goal.** `web/src/components/paper/PaperSidebar.vue` (the desktop TOC) and
`web/src/components/paper/MobileFloatingToc.vue` (the mobile floating TOC)
heretofore rolled their own table-of-contents state — `userExpanded` /
`userCollapsed` reactive Sets, an `isSectionExpanded` predicate, a
`handleSectionClick` / `selectRootSection` toggle, and a hand-rolled
`grid-template-rows: 0fr → 1fr` collapse animation in the desktop sidebar.
None of this leverages glass-ui, whose `@mkbabb/glass-ui/sidebar` subpath
already ships the canonical composable for exactly this shape.

**Completion criterion.** Both consumers delegate expand/collapse state to
glass-ui's `useSidebarState`; the desktop sidebar's subsection-row
animation is driven by glass-ui's `Collapsible` + `CollapsibleContent`
primitives; the active-section indication, scroll-progress through TOC
hierarchy, and click-to-scroll behaviour preserve their prior UX. Both
files typecheck (`vue-tsc -b --force` exit 0) and the production bundle
builds (`npm run build` exit 0).

## Substrate observed

glass-ui at the consumer pin already ships, under
`@mkbabb/glass-ui/sidebar`:

- `useSidebarState` — the userExpanded / userCollapsed reactive-Set pair,
  plus `isExpanded(id)` and `toggleSection(id)`, plus a `treeIndex` of
  hierarchy metadata, plus `isActive(id)` / `isInActiveChain(id)` helpers.
  Prior shape: hard-pinned to `sections: SidebarSection[]` (i.e. trees
  whose children live under `node.children`).
- `useScrollTracker` — IntersectionObserver-driven active-section
  tracking with a scroll-event fallback, generic over `T extends TreeNode`
  and accepting a custom `getChildren`.
- `useSidebarFollow` — damped sidebar scroll-follow, used by `PaperView.vue`
  via `latex-paper`'s passthrough.
- `useTreeIndex<T>` — generic flat index with `getChildren` override.
- `Collapsible` / `CollapsibleContent` / `CollapsibleTrigger` (re-exports
  of reka-ui's primitive) — drive the `--reka-collapsible-content-height`
  CSS-var-based expand/collapse animation.

The asymmetry: `useTreeIndex` and `useScrollTracker` were already generic
over `T` with `getChildren`; `useSidebarState` was not. Since
`PaperSectionData` stores children under `subsections` rather than
`children`, `useSidebarState` could not be adopted at the consumer
without coercing the domain type — a non-starter under the *no quick fixes*
discipline.

## Chosen architecture — **2 + augment** (composable adoption with
substrate augmentation)

The substrate gap was closed by **augmenting** `useSidebarState` to:

1. Be generic over `T extends TreeNode` (matching its `useTreeIndex` /
   `useScrollTracker` siblings).
2. Accept an optional `getChildren` that is forwarded into the inner
   `useTreeIndex<T>`.
3. Accept `activeId` / `activeRootId` as `MaybeRefOrGetter<string | null>`
   rather than `Ref<string | null>` — this discharges the cross-package
   Vue patch-version skew (`@vue/reactivity` 3.5.30 in fourier vs. 3.5.34
   in glass-ui) that otherwise imposed a `RefSymbol` identity check at
   the call site.
4. Surface a new `GenericSidebarState<T>` return type from the typed
   overload; the original `SidebarSection` overload preserves the
   `SidebarState` return identity.

`PaperSidebar.vue` and `MobileFloatingToc.vue` then consume the augmented
composable:

```ts
const sidebarState = useSidebarState<PaperSectionData>({
    sections: props.sections,
    activeId: () => props.activeId,            // getter — no Ref skew
    activeRootId: () => props.activeRootId,
    scrollTo: (id) => props.scrollTo(id),
    scrollToTop: () => props.scrollToTop(),
    getChildren: (n) => n.subsections,         // domain-specific
});
```

`PaperSidebar.vue` additionally wraps the subsection-row column in
`<Collapsible :open=… @update:open=…>` + `<CollapsibleContent>`,
retiring the hand-rolled `grid-template-rows: 0fr → 1fr` shim (and its
`opacity` co-animation) for the canonical `data-state="open"|"closed"`
animation channel driven by reka-ui.

`MobileFloatingToc.vue` adopts `useSidebarState` symmetric with the
desktop sidebar but keeps its existing `v-if`-driven dropdown reveal —
the mobile floating-TOC dropdown is a different visual pattern (slide
from below the sticky bar) and not a row-by-row collapse, so
`Collapsible` is not the right tool there. Its `selectRootSection` and
local `userExpanded` / `userCollapsed` Sets are gone; the sidebarState's
`isExpanded` / `toggleSection` discharge them.

## glass-ui carry — augmentation discharged at this seam

The augmentation lands at glass-ui (subpath `./sidebar`):

- `src/composables/sidebar/useSidebarState.ts` — generic over
  `T extends TreeNode`; accepts `MaybeRefOrGetter` for activeId /
  activeRootId; accepts optional `getChildren`; new `GenericSidebarState<T>`
  return type via overload.
- `src/composables/sidebar/index.ts` — re-export `GenericSidebarState`.

The augmentation is **structural** (it widens the contract; it does not
narrow it) — the prior `useSidebarState(options): SidebarState` overload
is preserved verbatim, so the in-tree `SidebarSection` consumers in
glass-ui's own demos remain typesafe with no source-level changes.

## Residual carries

None at the architectural level. Two minor observations filed but not
discharged at this seam:

- `latex-paper`'s `vue/index.ts` re-exports its own `useSidebarFollow` and
  `useTreeIndex` rather than re-exporting glass-ui's. This is a sibling
  concern (latex-paper predates the glass-ui v1.0 subpath surface) and
  outside W3.5.c's bounds — filed for `latex-paper`'s next wave.
- `useSidebarState` returns a `treeIndex` and `isActive` / `isInActiveChain`
  that the consumer here does not use (the consumer's `PaperView.vue` calls
  `useTreeIndex` directly via latex-paper for the active-chain helpers).
  The duplication is benign — the composable's tree index is built once
  per mount and not exposed in the consumer's bindings.

## UX preservation verdict

**Scroll-progress + active-section indication: WORKING.** Both behaviours
are driven by `useVirtualSectionWindow` (latex-paper) and `useSidebarFollow`
(glass-ui via latex-paper passthrough) — neither was touched by this
refactor. The refactor scope is bounded to expand/collapse state and the
subsection-row reveal animation, both of which now flow through
`useSidebarState` + `Collapsible`.
