## §1 — What the surface IS

The workspace is a two-zone `Configurator` (glass-ui) shell: a **stage** (the canvas) and a **controls aside** (the panel stack). `VisualizationView.vue:194-278` wires the chassis; `:296-319` makes it flex-fill the column and sets the aside width band (`320→360→400→440px` at the 1024/1280/1536 breakpoints).

**Stage (`#stage` slot, `VisualizationView.vue:196-250`)** — an absolutely-positioned crossfade pair: `BasisCanvas.vue` (the live epicycle/multi-basis renderer) and `ContourEditorCanvas.vue` (the point editor), toggled by `isEditing` with an opacity crossfade (`:363-380`). Overlaid on the stage: a top `CanvasControlsDock` (view-options popover, publish, equation, edit, fullscreen — `CanvasControlsDock.vue`), an `EquationPanel` flyout (`EquationPanel.vue`), and a bottom `AnimationControls` dock (play/scrub/speed/export — `AnimationControls.vue`) or `EditorControlsDock` in edit mode.

**Controls aside (default slot, `VisualizationView.vue:253-277`)** — a `panel-swap` transition between an editor stack and the viz stack. The viz stack is: `ImageUpload.vue` (the right-panel dropzone), then `BasisSelector.vue` (`ConfiguratorLayer` "Decomposition"), `ContourSettings.vue` (`ConfiguratorLayer` "Contour"), `CoefficientsPanel.vue` (`ConfiguratorLayer` "Coefficients" → `FrequencyGraph`). Each appears via `slide-down` as data arrives (`v-if="hasData"` / `hasImage`).

**The canvas renderer (`BasisCanvas.vue`)** — when empty it paints a placeholder (`lib/canvas-drawing/placeholder.ts`): a faint grid, a dashed rounded box, an upload arrow, and the text "Drag & drop an image here" (or "Computing…"). When populated it draws epicycle circles + connecting arm + golden trail + tip dot + ghost path + per-basis curves with hover-driven golden shimmer (`BasisCanvas.vue:120-372`), plus `N = …` / `t = …` labels with hit-regions for hover.

**Upload paths (three of them)** — (a) the right-panel `ImageUpload.vue:88-110` dashed dropzone "Drop an image or click to upload"; (b) the center-canvas placeholder, which is click-to-upload via a hidden file input (`VisualizationView.vue:126-136`, `198` `canvas-clickable`); (c) a global "Drop image anywhere" full-screen overlay on drag-enter (`VisualizationView.vue:144-153`). All three feed `store.uploadImage(file)`.

**The empty state (screenshot)** — shows (a) and (b) **simultaneously**: the right-panel "Image — source input" box AND the center "Drag & drop an image here" box. This is the headline IA finding below.

## §3 — Top refinements for D's design thread

Ordered by value. All are surgical — they keep the `Configurator`/`cartoon-card`/dock chassis intact.

1. **Resolve the dual-dropzone IA (A2-01).** This is the headline. The empty state currently presents two competing full dropzones with divergent copy and styling. Collapse to **one hero dropzone in the canvas** + a **slim source strip** in the panel (which expands to the thumbnail/replace card only once an image exists). Single primary CTA, single spatial mapping (upload where the result appears), unified copy. Highest clarity gain for the product's front door.

2. **Fix the three WCAG fails as one sweep (A2-02 + A2-03 + A2-09).** Canvas placeholder text (3.05:1), the panel's `/60` and `/70` muted hints (3.28:1, 3.96:1), and the dropzone border (2.41:1) all miss their floors. The root cause is two patterns: hardcoded `rgba(150,150,150,…)` on the canvas and opacity-modifier-on-an-already-muted-token in the DOM. Replace the canvas literals with the resolved `--muted-foreground` hex (the `resolveVizColors` plumbing already exists at `lib/colors.ts:90`), and drop the `/60`–`/70` modifiers. One contrast pass clears all three.

3. **Give the empty state a value prop + "Try an example" (A2-04 + A2-05).** The core product screen opens to two empty voids and no explanation. A one-line "Upload a shape — watch Fourier epicycles trace it" plus a bundled sample image transforms a cold upload form into an inviting demo, and rebalances the lopsided composition. No new layout — paint it into the existing placeholder / hero zone.

4. **Unify the loading/computing language and reveal the contour early (A2-07 + A2-08).** Today there are three loaders in three visual languages, and the canvas can read "Drag & drop…" while the panel shows a compute bar. Pick one canonical canvas-compute treatment, and draw the ghost contour the instant `extractContour()` resolves (before epicycles finish) to cut perceived latency on the central interaction.

5. **Make the mobile workspace observable (A2-10).** The hard Controls|Canvas tab toggle means every harmonics tweak on mobile is blind. Either pin the canvas above a controls sheet, or — minimum — default to the Canvas tab once data exists. The auto-recompute already fires on a 1s debounce; the user should be able to see what it produced without a tab round-trip.

## §4 — Strengths (preserve, do not touch)

- The `Configurator` stage|aside chassis (B.W2/W4) is a clean, principled IA: canvas-first stage, layered control panels. The B.W4 explicit stage-fill fix (`VisualizationView.vue:344-358`) is sound.
- The dock pattern (`GlassDock` collapse-on-idle, `CanvasControlsDock` + `AnimationControls`) keeps chrome off the canvas and is well-labelled for AT.
- A11y keystones from B/C are real: `FullscreenViewer` focus-trap + focus-return (`:30-101`), `ExportModal` via reka-ui Dialog with `aria-modal`/focus-trap (`:46-49`), `prefers-reduced-motion` guards on the rainbow play button (`AnimationControls.vue:176-178`) and the advanced collapse (`ContourSettings.vue:368-373`), sliders carry `aria-label` (`BasisSelector.vue:163,173`; `GlassTimeline.vue:71`).
- Motion is token-driven (`--ease-*`, named transition properties, no `transition: all`) per A.W3.d — the crossfade between canvas/editor and the `slide-down` panel reveals are tasteful.
- The golden-shimmer hover on basis curves + the rainbow play button are distinctive brand motifs that escape generic-AI aesthetics. Keep them.
