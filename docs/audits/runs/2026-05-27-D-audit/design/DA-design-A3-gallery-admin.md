## 3. Highest-value refinements for D's design thread

1. **Resolve the orphans, and let the marquee earn the empty state (findings #1, #12).** The single highest-leverage move: the empty `/gallery` is currently a cold dead-end (a 30%-opacity icon over near-black), yet a fully-built dual-track `GalleryMarquee` sits unmounted. D should *either* mount the marquee as a seed/sample band behind the empty copy — turning the cold state into a living preview of what the gallery becomes — *or* delete both orphans. Whichever way, pair the empty copy with a real `→ Open the Visualizer` button routing to `/visualize`. This converts the only directly-observable state from "nothing here" to "here is what's coming, start one."

2. **Close the keyboard/focus + dialog-role gaps (findings #4, #5).** The card is unreachable by keyboard and the detail modal is a roleless, un-trapped div. These are the two true a11y defects in the surface. Making the card a `role="button"` focusable control and re-pointing the modal onto the glass-ui `<Dialog>` (already the surface's confirm-dialog primitive) fixes both *and* unifies the modal idiom — high value, low surface area.

3. **One contrast pass on the dimmed metadata (finding #3).** Swap every `text-foreground/35` and `text-muted-foreground/60` for the AA-tuned tokens that already exist (`--muted-foreground` L62, `--muted-foreground-strong` L72). This is a find-and-replace across card + modal that lifts timestamps and stat labels from ≈1.9:1 to AA without changing the visual register — the tokens were *designed* for exactly this.

4. **Unify the card-width regime (finding #6).** Pick one `minmax` track token and apply it to carousel + grid so a card does not resize when it is featured vs. listed. This is the most visible inconsistency a populated gallery will show, and it is one shared CSS var.

5. **Make the moderation surface legible without a pointer (findings #7, #8).** The flagged panel is the surface where wrong = irreversible deletion, yet its destructive action is colour-on-hover only and its decision data is at 10px. Carry the Delete tint at rest and step the flag-reason lines to 12px. Small edits, outsized safety payoff on the admin surface C.W4 just reshaped.

## Notes on scope
- Only the empty state is directly observable (local DB empty); all populated / carousel / marquee / admin findings are inferred from source and cited at `file:line`. A populated capture in a later wave would let us confirm the card-width discontinuity (#6) and the carousel-vs-grid gap visually.
- C.W4's reshape of `AdminFlaggedPanel` (cursor envelope + `FlaggedVisualization` type, cast removed) reads clean at the UI layer: the cursor "Load more" (`:241-261`) is a coherent replacement for offset pagination, the `role="list"`/`listitem` semantics are correct, and the confirm-dialog supplanting native `confirm()` is the right call. The residual issues are the rest-state colour (#7) and 10px type (#8), not the C.W4 wiring itself.
- This is a refinement audit: every recommendation reuses an existing token, primitive, or component. Nothing here proposes a new visual language.
