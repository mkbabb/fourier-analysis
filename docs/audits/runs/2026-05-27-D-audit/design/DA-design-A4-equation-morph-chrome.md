# DA-design-A4 — Equation + Morph + Shape-extractor + Cross-cutting Chrome + Dark-mode Parity

**Lane:** A4 — design refinement audit (frontend-design lens), the "long tail" + the cross-cutting chrome
**Scope:** `/equation`, `/morph`, `/demo/shape-extractor`, the global header/nav, the theme-token system, and dark↔light parity across ALL routes
**Framing (per DA6):** this is an AUDIT of the SHIPPED surface — per-screen findings + surgical refinements, NOT a redesign or rebrand. READ-ONLY: no source touched. Refine, don't rebrand.
**Date:** 2026-05-27
**Screenshots:** `screens/d-equation.png`, `screens/d-morph.png`, `screens/d-shape-extractor.png` (plus `d-visualize.png`, `d-gallery.png`, `d-paper.png` for cross-screen chrome).
**Live validation:** Playwright against the running dev server (`http://localhost:3000`) — computed styles, WCAG ratios, and a light-mode render were measured, not eyeballed.

## 1. What the surfaces ARE

### Cross-cutting chrome — the global shell (`App.vue`, `AppHeader.vue`)

- **App shell** (`web/src/App.vue:23`): `h-dvh` flex column, `bg-background text-foreground paper-texture overflow-hidden`, a sticky `AppHeader` over a single scrolling `<main>`. `App.vue:9-17` mounts a `MutationObserver` on `documentElement.class` that re-resolves the JS-side viz palette (`resolveVizColors()`, `lib/colors.ts:90`) on every dark↔light toggle — a genuine, deliberate theme-sync mechanism.
- **The wordmark identity** (`AppHeader.vue:64-66`): "**ℱourier analysis**" — the ornamental `ℱ` (`U+2131`) rendered through the `.fourier-f` display face, the rest in `.cm-serif` (Computer Modern Serif). It is a HoverCard trigger (`AppHeader.vue:54-96`) revealing the `@mbabb` GitHub attribution card. This is a strong, distinctive identity well clear of generic AI aesthetics. Note: the wordmark is **serif**, not monospace — the brief's "monospace wordmark" is a misread; the monospace register (Fira Code, `.fira-code`) is used for the attribution handle, numeric inputs, and status text, not the logo.
- **The nav** (`AppHeader.vue:100-120`): a SINGLE dropdown `Button` showing the active tab's icon + label + chevron, tinted amber (`--viz-amber`, `AppHeader.vue:183,189`). Opening it reveals the 5 routes (Paper / Visualize / Gallery / Equation / Morph, `AppHeader.vue:23-29`). This is consistent across every route by construction.
- **Right cluster** (`AppHeader.vue:122-128`): optional admin badge, `UserSlugBar` ("Log in"), and the dark-mode toggle.
- **The "eye" toggle** the brief mentions is NOT a separate control — it is the nav-dropdown trigger showing the `Eye` icon when `/visualize` is the active tab (`AppHeader.vue:25`). The actual theme toggle is the **sun↔moon Fourier-morph crescent** on the far right (`DarkModeToggle.vue` → `FourierMorphSvg`), which animates an epicyclic morph between a sun (warm `#E88845`) and moon (legendre `#c084fc`) on click (`DarkModeToggle.vue:62-72`). This is a delightful, on-brand signature control.

### Theme tokens — there IS a real design-token system

Tokens are NOT ad-hoc. They live in the linked `@mkbabb/glass-ui` (v2.0.0, `file:../../glass-ui`) under `dist/styles/tokens.css` + `theme.css`, with a full **light (`:root`) and dark (`.dark`) parity set**: core semantics (`--background/--foreground/--primary/--border/--muted-foreground/--ring`), a 13-stop jewel-tone `--section-color-*` palette (light `tokens.css:451-463`, dark `tokens.css:1326-1338`), and the brand `--viz-*` basis hues (`--viz-fourier/chebyshev/legendre/amber/green`, light `tokens.css:472-476`, dark `tokens.css:1342-1346`). The app overrides only `--font-sans → Computer Modern Serif` (`style.css:14`) and adds KaTeX font-face swaps + a tab-panel entry animation. This is a mature, coherent token foundation — the app rides it well in MOST places.

### `/equation` (`EquationView.vue` + `FunctionInput.vue`)

A `360/400/440px + 1fr` two-pane grid on `lg` (`EquationView.vue:337-349`), collapsing to a mobile `UnderlineTabs` Controls/Canvas switch (`EquationView.vue:186-191`). Left: `FunctionInput` (expression text input, domain fields, Compute, preset pills, harmonics/display-terms sliders, notation pills) wrapped in collapsible cards; an animated `EqCoefficientsPanel`. Right: the rendered Fourier-series equation card with a per-coefficient KaTeX hover popover (`EquationView.vue:257-265`), a mode toggle (Σ / expanded), a tier/energy info HoverCard, and a `ConvergencePlot`. The dark screenshot `d-equation.png` caught a transient "Computing…" spinner (API slow); the live light render confirms the full surface composes correctly (convergence plot, equation, coefficient spectrum, presets).

### `/morph` (`FourierMorphDemo.vue`)

A centered `max-width:960px` page (`FourierMorphDemo.vue:183-193`). A title/subtitle header (`demo-title`, serif `2rem`), a large interactive morph-preview button + info chips (`MorphShapePreview.vue`), three phase-config cards (Settle Out / Morph / Settle In — duration + easing, `MorphPhaseConfig.vue`), a harmonic-level grid (`HarmonicLevelGrid.vue`), and an Export/Reset row (`FourierMorphDemo.vue:70-79`). This is a polished, considered tuning surface.

### `/demo/shape-extractor` (`FourierShapeExtractor.vue`)

A raw **internal developer tool** (router `index.ts:57`, NOT in `VALID_TABS`, unreachable from nav). It renders two reference SVGs (sun, moon) drawn with hardcoded `stroke="red"` + `#ccc` borders, an "Extract Shape Contours" button, and a `<pre>` JSON dump (`FourierShapeExtractor.vue:1-138`). It uses **inline styles, bare `<h1>/<h2>`, zero tokens, zero scoped CSS, zero theme awareness** (`d-shape-extractor.png` shows red shapes + a tiny JSON blob on the dark shell). It is functional scaffolding, not a designed surface.

**Net read:** the chrome and the equation/morph surfaces are confident and distinctive — the cut-paper card language, the CM-Serif identity, the ornamental `ℱ`, the sun/moon morph toggle, and a real token system are genuine strengths. The findings below are dominated by ONE high-severity regression (a deleted utility class that 14 components still rely on) plus a light-mode contrast cluster on the amber accent.

## 3. The 3–5 highest-value refinements for D's design thread

1. **Resurrect `.cartoon-card` globally (Finding #1) — the single biggest lift in the entire D design thread.** One class is dead and 14 components across equation, morph, gallery, and visualize silently lost their border + shadow + hover-lift. A ~3-line `@utility cartoon-card { @apply cartoon-surface; … }` shim in `style.css`, or a migration to `<Card surface="cartoon">`, restores the intended cut-paper surface language on every affected screen at once. This is a GLOBAL chrome refinement that lifts every surface — exactly the cross-cutting, highest-value class of fix the lane was asked to surface. Other lanes (A2/A3) almost certainly hit the same orphan; coordinate ONE fix.

2. **Fix the light-mode amber/golden contrast cluster (Findings #3 + #4) — the only a11y-contrast failures found, and they are GLOBAL.** Light-mode `--viz-amber` = 3.55:1 (the active nav label on EVERY route) and the hardcoded `#f0b632` text = 1.76:1 both fail WCAG AA. A single token change — darken light `--section-color-5` to ~`hsl(35 76% 35%)` and replace the two `#f0b632` text hardcodes with `var(--viz-amber)` — repairs the nav identity color app-wide and removes the worst ad-hoc colour in the codebase. Dark mode is already exemplary (foreground 15.46:1, muted 7.39:1, amber 10.58:1, all AAA), so this is a light-mode-parity repair, not a redesign.

3. **Unify the button + page-title vocabulary between Equation and Morph (Findings #6 + #7).** Morph hand-rolls `.btn-export`/`.btn-reset` and its own title scale while Equation uses glass-ui `Button` + tokens. Dropping morph's overriding classes onto the `<Button>`s it already wraps, and adopting one shared `.page-title`, removes ~50 lines and makes the two routes read as one product. Highest coherence-per-line ratio after #1.

4. **Gate / 10-minute-polish the shape-extractor (Finding #5).** It is dev-only and unreachable, so the correct move is to gate it behind `import.meta.env.DEV` in the router so it never ships, OR spend 10 minutes swapping `red→var(--viz-fourier)`, `#ccc→var(--border)`, bare headings → `.cm-serif`. Cheap, removes the one truly un-designed surface from the prod bundle.

5. **Add the global keyboard-focus + theme-toggle a11y polish (Finding #9, and mirror A1's focus-ring carry).** The header nav already has a correct `:focus-visible` ring (`AppHeader.vue:174-177`); make that the canonical pattern and ensure the sun/moon toggle and morph/equation interactive controls all carry it, plus an `aria-pressed` + Tooltip on the theme toggle. Small, app-wide a11y lift.

### Verdict notes

- **Dark-mode parity: PASS, and dark is the stronger of the two modes.** A full light↔dark token set exists in glass-ui with brightened section/viz hues for dark; the `App.vue` MutationObserver keeps the JS viz palette in sync; the `/equation` page renders fully and correctly in BOTH modes (live-verified). The ONLY parity defects are the light-mode amber/golden contrast failures (#3, #4) — repairable in tokens, not a structural absence. There is no "broken or absent" light mode.
- **Token system: REAL, not ad-hoc.** The handful of ad-hoc colours (`#f0b632` ×3, `red-400/red-500` raws, `red`/`#ccc` in the dev tool) are the exceptions to flag, not the rule.
